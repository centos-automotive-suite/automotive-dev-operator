# E2E Test Summary

Global `BeforeSuite` resolves namespace/registry/arch; `AfterSuite` tears down the namespace and port-forwards unless `E2E_SKIP_CLEANUP=true`. Most lanes additionally rely on shared setup helpers from `test/e2e/helpers_test.go` (memoized once per suite run), referenced in plain words below:

- operator deployed — CRDs installed, `ado-operator` deployed, OperatorConfig applied, Build API deployment ready
- Build API reachable — Route (OpenShift) or port-forward (Kind) set up to the Build API
- caib credentials provisioned — a `caib` ServiceAccount and token created for CLI calls
- registry configured — OperatorConfig registry settings and the `push-artifact-registry` Task patched for the target registry

## Notes

- Tests are grouped by Ginkgo `Label()` rather than strictly by file. CI and Makefile targets run lanes via `--label-filter` (PRs default to `smoke`). Labels in use: `smoke`, `operator`, `features`, `auth`, `bootc`, `internal-registry`, `package-mode`, `container-build`, `manifest-validation`, `catalog`.
- `test/e2e/scripts/gen-spec-index.sh` emits `Group | Test Name | Labels | Source`; use it to cross-check lane/label/test/file alignment against this document.
- Dual labels: Operator Health is `operator`+`smoke`; Package Mode Build is `package-mode`+`smoke` (so the smoke lane includes the package-mode disk build when `REGISTRY_HOST` is set).
- Several lanes self-skip via `Skip()` when prerequisites are absent (`REGISTRY_HOST` unset, non-OpenShift cluster, missing Shipwright CRDs, no Dex) rather than failing.
- `test/e2e/helpers_test.go` holds all shared setup/polling helpers; no test cases of its own.
